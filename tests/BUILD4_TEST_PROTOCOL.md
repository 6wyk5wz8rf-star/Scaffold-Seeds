# Scaffold Seeds Build 4 test protocol

This protocol verifies the local-first AI enhancement loop without calling an external AI service. Record browser, device, date, tester and any follow-up beside each section.

## 1. Build 3 regression

- Create at least one resource in every subject and every year band.
- Confirm the seven local design stages still work: Learning, Sticking point, Protect thinking, Choose support, Build, Review and Output.
- Generate every engine at Seed, Sprout, Growth and Independent.
- Confirm Independent removes task-completing support rather than leaving an empty copy.
- Edit instructions, example, prompts, vocabulary, teacher notes, response space and diagram labels.
- Regenerate one local section; confirm every other section remains unchanged.
- Save, refresh, reopen, create a named checkpoint, compare and restore it.
- Convert representative resources through all 18 formats.
- Print A4 portrait, A4 landscape, A5, mixed pack, four-card, eight-card, booklet and poster-tiling forms.
- Inspect colour, low-colour, greyscale, black-and-white, high-contrast and photocopy modes.
- Confirm there is no clipped content, hidden overflow, blank page, split card, tiny type or lost diagram label.

## 2. Prompt construction matrix

For each of the 13 subjects:

- Prepare a Quick prompt and confirm it contains the objective, narrow task, protected thinking and return format but omits non-essential bulk.
- Prepare a Professional prompt and confirm barrier, relevant local knowledge, engine structure, growth stage, subject safeguards and self-check are included.
- Prepare a Forensic prompt and confirm provenance, print constraints, uncertainty handling and source rules are included.
- Change task family and task; confirm the allowed content slot, expected sections, quantity, risk level and safeguards change.
- Confirm irrelevant subject rules are omitted.
- Confirm the prompt says what AI may change and what remains untouched.
- Confirm the prompt never asks AI to control page geometry, fonts, margins, stage labels, diagram rendering or fading.
- Test Professional task-specific controls for passages, questions, examples, models, misconceptions, vocabulary and teacher modelling.
- Copy primary, compact, structured, packet, image brief and verification-only forms.
- Download each as plain text and inspect it outside the app.
- Confirm the AI Prompt Packet includes teacher explanation, expected format, return instructions, checklist, scaffold summary and compact fallback.

## 3. Privacy and clipboard

Test prompt content containing each of the following, separately and together:

- full pupil name
- pupil initials
- email address
- UK phone number
- date of birth
- street address
- school name
- diagnosis
- safeguarding, trauma, medical, behaviour or family-history wording

For each case:

- Confirm the scrubber shows a cautious warning rather than claiming flawless detection.
- Apply neutral replacements and inspect every replacement.
- Copy the scrubbed prompt; confirm unsanitised text is not placed on the clipboard.
- Confirm the scaffold is autosaved before the copy confirmation appears.
- On iPad Safari, copy, switch apps, return and confirm the same resource, phase and prompt remain.
- Repeat in split-screen and with the on-screen keyboard visible and dismissed.

## 4. Import recovery matrix

Import each fixture below:

- plain structured text
- markdown headings
- bullets
- numbered lists
- pasted table
- valid simple JSON
- malformed JSON
- introductory AI commentary before content
- repeated headings
- numbering errors
- missing answers
- partial response
- unexpected section
- disclaimer after content
- code fence
- HTML, script and style fragments
- response near the 60,000-character local limit

For each fixture:

- Confirm the raw response is preserved.
- Try automatic structuring, plain text and manual mapping.
- Confirm no script, style or markup executes.
- Confirm expected, optional and unexpected sections are distinguished.
- Confirm missing sections and repeated items are flagged.
- Refresh during import and confirm recovery.
- Start over, then restore the original local scaffold.

## 5. Section review and comparison

- Accept all items in one section.
- Reject all items in another.
- Accept individual items 1, 2 and 5 only.
- Edit an item before accepting it.
- Keep the original local content for one section.
- Remap an uncertain block to Vocabulary, Questions, Answers, Teacher guidance, Model response and Ignore.
- Compare each proposed section with its original.
- Confirm added, removed, word-count and terminology changes are visible.
- Use the plain comparison and highlighted comparison.
- Prepare a regenerated prompt for one section; confirm the rest of the accepted content is named as protected.
- Use keep-best-six, remove-repeats, reduce-vocabulary, shorten-instructions, move-notes-off-pupil-page, explanations-to-bullets, stems-to-questions, split-into-two-pages and compact-card reflow.
- Confirm removed content remains visible in the decision/change record.

## 6. Deliberate verification failures

Import and accept each problem. Confirm the stated response:

| Problem | Expected response |
| --- | --- |
| `6 × 7 = 45` | Do not use yet · incorrect mathematical answer · local calculation |
| Inconsistent unit conversion | Do not use yet · calculation validated locally |
| Fabricated historical quotation without provenance | Do not use yet · source verification required |
| Primary source claim with placeholder URL | Do not use yet · possible invented citation |
| Science conclusion without data | Important review finding |
| Mass described as weight | Do not use yet · scientific misconception |
| Sentence frame supplies the inference | Important pedagogical drift finding |
| Independent stage receives examples and vocabulary | Important support-stage drift finding |
| “All Christians believe…” | Important universal-worldview finding |
| First-person faith testimony without source | Do not use yet |
| PSHE public trauma/family disclosure | Do not use yet |
| Unsafe secrecy message | Do not use yet |
| Colour-only instruction | Important inclusion finding |
| Fixed-ability label | Important pedagogical finding |
| Duplicate question | Structural review finding |
| Mismatched question and answer counts | Important structural finding |
| Circular vocabulary definition | Language review finding |
| Overlong PE cue | Subject review finding |
| Flowchart with one node | Do not use yet · malformed local representation |
| Text too dense for a desk strip | Print review finding |

Resolve and reopen findings. Confirm only unresolved `Do not use yet` findings block approval. Confirm every finding states a next action and one of: locally checked, calculation validated, structure matches request, pattern-based warning, teacher review required, source verification required or external verification recommended.

## 7. Subject specialist checks

- Mathematics: arithmetic, decimals, percentages, conversions, ambiguity, duplicate answer options and local diagram structure.
- English: phonics-programme caution, picture guessing, passage-question support, inference ownership, formulaic models and morphology claims.
- Science: enquiry type, observation/inference, evidence/conclusion, units and named misconception patterns.
- History: dates, quotations, provenance, reconstruction labels and source-usefulness language.
- Geography: place relationships, weather/climate, scale, keys, stereotypes and dated statistics.
- Computing: algorithm/code distinction, debugging leakage, personal-data requests and local manual trace mode.
- Languages: target language/variant requirement, accents, English intrusion and fluent-speaker review wording.
- Religious Education: local syllabus caution, internal diversity, testimony and quotation provenance.
- PSHE: fictional scenarios, disclosure safety, trusted-adult guidance and safeguarding boundary.
- Art, Music, DT and PE: disciplinary activity, terminology, user/purpose cycle, minimal cues and body-neutral wording.

## 8. Approval, versions and provenance

- Attempt approval without checking the human gate; confirm it is unavailable.
- Attempt approval with an unresolved `Do not use yet` finding; confirm it is unavailable.
- Use **Correct in review**, edit or reject the serious item, then re-run checks; confirm a `Do not use yet` finding cannot be dismissed without correction.
- Approve a section, current page and whole resource in separate rounds.
- Name rounds `First examples`, `Vocabulary revision`, `Accuracy check` and `Final critique`.
- Confirm a checkpoint is created immediately before each applied round.
- Confirm objective, protected thinking, engine, stage pathway and format remain unchanged.
- Confirm accepted content is rebuilt inside the local resource renderer.
- Confirm rejected changes and previous warnings remain in the private record.
- Confirm pupil printouts do not contain provenance, AI status or private teacher review data.

## 9. Growth pathway and mixed packs

- Apply shared accepted content across Seed, Sprout, Growth and Independent.
- Apply a support item to Seed only.
- Confirm common content remains comparable across stages.
- Confirm Scaffold Seeds—not imported content—controls what fades.
- Confirm Independent does not regain examples, sentence completions or selected answers.
- Generate a mixed pack and check that higher-support pages do not reveal answers used on lower-support pages.
- Confirm pupil-facing pages use no public fixed-ability or AI-assisted label.

## 10. Images

- Import a PNG, JPEG and WebP under 2.5 MB.
- Reject an unsupported type and a file over 2.5 MB.
- Add caption and alt text; rotate; switch contain/crop; preview greyscale.
- Confirm the image never leaves the browser.
- Confirm a large-file storage warning appears.
- Confirm the local sampled contrast, estimated ink coverage and 300-ppi print-size guidance appears, then inspect final greyscale legibility manually.
- Confirm a precision-critical diagram remains in the local SVG system.

## 11. Library, persistence and portability

- Filter local only, prompt prepared, response imported, needs review, approved, unresolved warning and source attached.
- Select several resources and export them.
- Batch mark reviewed; confirm no resource is bulk approved.
- Include an unresolved high-risk resource and confirm it is not marked reviewed in bulk.
- Batch archive and restore.
- Refresh after prompt preparation, raw import, section decisions, findings and approval.
- Switch between two in-progress AI resources; confirm each restores its own workspace.
- Close and reopen the browser after copying a prompt.
- Export a full backup with raw response history and restore it.
- Export a smaller backup without raw response history and restore it.
- Export one portable resource and import it in a clean Scaffold Seeds installation.
- Corrupt a stored workspace and Build 3 resource separately; confirm graceful recovery without erasing other resources.
- Approach local-storage capacity with image-heavy resources; confirm a storage issue is reported without crashing.

## 12. Browser, accessibility and performance

Run the complete loop in current Chrome, Safari and iPad Safari at desktop, 1024×768 and 768×1024.

- Keyboard-only: every task, tab, decision, finding, source field and approval control is reachable.
- Screen reader: phase navigation, status, forms, progress and imported sections have meaningful labels and order.
- Visible focus is retained.
- No control relies on hover alone.
- Touch targets are usable and no horizontal page scroll appears.
- Reduced motion, high contrast and enlarged interface text remain usable.
- Prompt construction, a 60,000-character import, comparison and verification feel immediate.
- Verification does not run on every keystroke.
- Large libraries filter without an extended blocked state.
- Print preview does not lose the in-progress AI workspace.

## Automated command

```sh
node tests/build4-engine.test.js
```

The automated suite covers prompt architecture across all subjects and all three depths, engine metadata, privacy patterns, import recovery formats, sanitisation, section acceptance, provenance, deterministic maths, subject risk patterns, vocabulary, diagram structure and computing trace behaviour. Browser and physical print checks remain manual where the runtime cannot establish real Safari or printer behaviour.
